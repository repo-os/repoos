# Changelog

Every RepoOS release, newest first. This file is generated by the release
pipeline from `release-history.json`; the newest entry is also the GitHub
release body. The full discussion of each change lives in the release notes
and on GitHub.

## [v0.5.77] - 2026-11-06

### More reliable Muse engineering runs

Muse engineers can now run with a higher step limit, clearer notice when that limit is reached, and smoother handling of streamed output. They’re also guided to scope screenshot selectors to the relevant fixture card.

### Expanded Muse model support

The available Muse models now include Spark 1.3, Spark 1.2, and Wonder 1.0. Native Muse drivers for Spark 1.3 and Contributor can also be included in the budget allowlist.

[Release on GitHub](https://github.com/repo-os/repoos/releases/tag/v0.5.77)

## [v0.5.76] - 2026-11-05

### A Pipeline view for work in flight

The Work page has a new **Pipeline** view alongside the board. Each active or review task gets its own lane and moves through **Coding → Checks → Handoff → Review → Close-out → Merged**, so you can see at a glance where everything stands, including rounds, models, and whether a task ran locally or on a remote runner. Recently merged tasks stay in the Merged column for a short window, tasks sent back from review carry an amber “sent back” note, and stuck, held, or paused tasks keep their stage with a clear state chip. Stages update live, clicking a card opens the usual task panel, and the view remembers your choice. The board remains the default.

### Installs and uninstalls now match reality

- The curl installer puts the program in `~/.local/share/repoos` and keeps machine state in `~/.repoos`, so reinstalling no longer wipes running-server and check-slot state.
- `repoos uninstall` removes what it owns and tells you exactly what it left behind; per-repo configuration and caches are untouched.
- The installer now enforces Node **20.6.0+**, not just “Node 20”, and the docs explain the Bun/pnpm `PATH` setup steps.
- mise is no longer presented as a recommended install method; its download threshold and minimum release age made it install the previous version.
- The Homebrew formula’s Node dependency is now documented rather than left as a surprise, and install examples consistently use `curl … | bash`.

### Clearer task and agent state

- Close-out progress in the task panel now appears as a full-width status line between the preview row and the tabs. It no longer looks like a button or pushes **Stop MTD** onto its own row.
- `repoos driver brief` and the CTO no longer call an engineer “stalled” while its check is running with a live heartbeat, so a healthy check cannot be interrupted by a restart.
- PM-added sections such as Problem, Desired UX, and Acceptance criteria now land above the original freeform prompt and screenshots instead of being buried below them.
- The macOS Hub CI job no longer fails on every run because of a keyboard-focus test that could not hold focus on a headless runner.

### Interface polish

- The **Hold task** dialog uses the same outlined fields as the rest of the app, allows holding without a reason, and the held card handles a missing reason without a blank row or cramped padding.
- **New schedule**, **New reminder**, and **New environment** now match **New task**: accent style, plus icon, and top-right placement.
- The task-card agent popover fades out after 15 seconds by default; the delay is configurable in Settings, `0` disables it, and interacting with the popover resets the timer.
- The optional commit-message field in the Uncommitted changes panel is about three lines tall instead of filling most of the panel.

### Smoother setup and CLI

- `repoos init` templates no longer reference paths that do not exist in a new project, so `repoos doctor` starts clean.
- The `serve` banner states which interfaces are bound, and the docs explain Tailscale detection and how to force localhost with `--host 127.0.0.1`.
- Zero-commit repositories and Git identity supplied through environment variables are handled correctly by `repoos status`, `repoos new`, and `repoos init --new`; auto-committing on `new` is now documented.
- `repoos list` prints one short notice instead of a long warning when no server is running.
- Saving a schedule warns when its task template is missing Problem, Acceptance criteria, or Notes for AI — advisory, with a badge on the schedule card and the same warning from `repoos schedule new` and `update`.
- CLI docs now cover `repoos uninstall`, `repoos service`, and `--version`, and several messages point to the right docs and describe the runtime accurately.

[Release on GitHub](https://github.com/repo-os/repoos/releases/tag/v0.5.76)

## [v0.5.75] - 2026-11-04

The web app no longer eats your CPU while idle, and engineer agents survive server restarts

**Top priority in this release was making RepoOS cheaper to run and less likely to stall your work in flight.**

### A quieter web app
An open dashboard used to burn 30–97% of a CPU after a day or two in a tab or PWA window, loaded the server, and in bad cases dragged whole-machine load up with it. Idle work in the renderer has been found and fixed: when nothing is changing, an open board costs essentially nothing. When the tab is hidden, polling and animations pause. Memory stays bounded over long sessions.

### Engineers survive server restarts
An engineer agent that was mid-task when the server restarted used to silently go idle afterward — it looked alive to the new server process, but queued messages were never delivered and no progress was made until someone stopped and started it by hand. Restarting the server mid-task no longer needs your intervention: an adopted engineer that can't communicate is now detected and restarted automatically, and queued messages get delivered instead of sitting overdue for an hour.

### Smoother closing out tasks
- **Move to done no longer fails for bookkeeping churn.** Previously, publishing a finished task could abort **after the entire validation gate** (which can take 10–25 minutes) just because other live tasks' task files were momentarily dirty on `main` — a routine state when several engineers are running. That no longer blocks the merge; genuinely dirty source files and repo settings still do.
- **Review timeouts are now fair.** Reviews were cut off at a hard-coded 15 minutes, so large diffs on slower models died mid-review with a confusing "no usable report," ate a review round, and needed a manual retry. The timeout is now configurable in Settings, a timeout is reported as a timeout (not a missing report), and one automatic retry happens before your attention is asked for.
- **Engineering reports count only your words.** The 1,000-word cap used to include the server-generated change summary and file list, so a task touching many files got rejected at handoff even with a short report. The cap now applies to the engineer's own narrative only (soft target ~1,000, hard cap 1,200 words), regardless of diff size.

### Project history that outlives your machine
- **Review reports are now committed to the repo**, side by side with engineering rounds under `work/reports/<task-id>/`. Previously they lived in a local, gitignored cache and vanished with it — leaving no record of why a task passed through several review rounds. Existing reports were migrated and old locations still read.
- **Worktree cleanup is safer and explains itself.** Clean worktrees for merged tasks are now reclaimed automatically at boot and close-out, instead of piling up until a manual `repoos gc`. `repoos gc --dry-run` and status distinguish safe candidates from entries kept for a stated reason (unmerged commits, dirty source, active or human-owned work — all preserved), and outside-RepoOS worktrees are never touched.

### Fixes and smaller improvements
- Stray test helper processes no longer accumulate for days, adding memory pressure and stalling checks. Test runs kill everything they spawn on teardown, and a background reaper (every 10–15 minutes, never matching by process name, never touching live work) cleans stragglers that slip through.
- The "Cancel stalled check" button on a task no longer flickers on and off every few seconds while a check is progressing.
- In the task drawer, the Review and Engineer report tables no longer let the selected row's accent bar cover the pass number, and the Dev tab now uses the same layout and styling as the Review tab (Report on the left, Chat on the right, with the model selector always visible above).
