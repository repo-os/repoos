## Problem

Task `#0059` added a sticky save bar to the Agents page with a prominent
**Save agents** button whenever there are unsaved changes. But there is no way
to throw those edits away and start over: once a user has made changes they
either save them or navigate away (which now triggers a confirm prompt). A
"changed my mind" path is missing — reverting means hand-undoing every edit or
reloading the page.

## Desired UX

Next to the **Save agents** button in the save bar there is a second button,
**Discard Edits**, that is visually less flashy than the primary save button:

- When there are unsaved agent changes, **Discard Edits** sits beside **Save
  agents** in the save bar and reverts all local edits back to the last saved
  config in one click.
- It is intentionally understated (secondary/outline/ghost styling) so the
  save action stays the obvious primary affordance — "less flashy".
- After discarding, the page reflects the saved state: the save bar recedes to
  its neutral/clean look and the "Unsaved changes" indicator disappears.
- The save behavior is untouched: same validation, "Saving…" state, and
  success/error messages.

## Acceptance criteria

- [ ] A **Discard Edits** button appears in the Agents save bar next to
      **Save agents**, styled less prominently than the save button
      (secondary/outline/ghost, not the highlighted accent)
- [ ] Clicking **Discard Edits** when there are unsaved changes reverts the
      agent list to the last saved config and clears the dirty state
- [ ] After discarding, the save bar returns to its clean/neutral state and the
      "Unsaved changes" indicator is no longer shown
- [ ] The button does not act when the page is clean (no unsaved changes): it
      is either hidden or disabled, and does not interfere with the save bar's
      subtle clean state
- [ ] Save behavior is unchanged: validation, "Saving…" state, and
      success/error messages still work as today
- [ ] `repoos check` passes

## Notes for AI

- **File to touch**: `src/ui-app/src/views/AgentsView.vue`. The save bar is in
  the template's `.save-bar.agents-savebar` block (~lines 398–419), inside a
  `div.save-actions` that currently holds only the **Save agents** `Button`.
  `localAgents` is defined at line 20; `sync()` (line 23) already resets
  `localAgents` from `config.agents` — reuse it for the discard action.
- **"Less flashy" interpretation**: the save button uses `variant="default"`
  plus a `dirty` accent class; the discard button should use a quieter variant
  (e.g. `outline` or `ghost`) and no accent styling.
- **Placement**: put **Discard Edits** immediately to the left of **Save
  agents**, keeping Save as the rightmost/primary action.
- **Assumptions** (the user did not specify): the discard button appears only
  when there are unsaved changes (`dirty`) — with nothing to discard there is
  nothing to show. A one-click discard with no confirmation is assumed, since
  the button's purpose is explicit; do not add an extra confirm dialog.
- **Don't**: don't change the save path, validation, or agent config schema;
  don't add autosave; don't touch other pages; no new runtime dependencies.
- **Self-hosting rule**: this repo runs itself — after the UI change run
  `bun run build:ui`, keep `repoos serve` running, and probe the page (make an
  edit → both buttons visible; discard → clean state) in a browser before
  reporting done.
