## Problem

We're about to build an Astro landing page and we already have a GitHub
README. Both need screenshots of the Web UI, but the UI is changing fast
(three themes now: classic, clear, gen z — each dark and light). Hand-made
screenshots rot immediately: they show old themes, stale task lists, and a
messy local repo state. There's no canonical `screenshots/` folder and no
repeatable way to regenerate them.

## Desired UX

- A `screenshots/` folder at the repo root holding the latest captures of the
  main Web UI features: dashboard, work board, the open task drawer, the
  repo/context docs view, and settings.
- Screenshots are generated by a script (not by hand) against a controlled
  sample repo, so they always show curated, realistic-looking tasks across
  every status column and the current design language.
- The captures are deterministic and independent of the developer's own
  `repoos.toml` and `work/` state (no PATCHing the user's live config).
- `repoos check` fails with a clear message when the committed screenshots are
  stale relative to the UI source, so they can't silently rot.
- A short `screenshots/README.md` explains what each image shows and how to
  regenerate (`bun run screenshots`).

## Acceptance criteria

- [ ] `screenshots/` contains one PNG per feature (dashboard, work board, task
      drawer, docs context, settings), all generated from the built app
      (`dist/`) served on an ephemeral port.
- [ ] `scripts/capture-screenshots.mjs` generates them against a fixture repo
      (sample `repoos.toml` + sample `work/*.md` + sample `docs/*.md`) with
      zero console/page errors, using the same WebKit + `startServer` pattern
      as the `repoos check` UI smoke test.
- [ ] The generator never touches the developer's real `repoos.toml` or
      `work/` files.
- [ ] `repoos check` includes a screenshots-freshness gate that fails with
      "Screenshots are stale — run `bun run screenshots`" when the UI source
      hash differs from the committed one (skipped if Playwright is absent).
- [ ] `bun run screenshots` regenerates everything and leaves a clean git
      status for the PNGs and the freshness marker.
- [ ] `screenshots/README.md` documents the images and the regeneration
      workflow.

## Notes for AI

- Server: `startServer({ root, host, port: 0 })` from `src/server/server.ts`
  accepts a root — point it at a temp copy of the fixtures so the user's real
  config is untouched. Ephemeral port means it works even when the dev server
  is running.
- Drawer: clicking a `.task-card` on `/work` opens the task drawer
  (`ui.openTask`).
- Routes: `/` dashboard, `/work` board, `/repo` docs/context, `/settings`.
